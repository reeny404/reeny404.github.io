Case 03 · 미리디

미리캔버스 저장과 결제 안정화

MAU 200만(2021년 기준) 웹 디자인 도구에서 저장 실패와 초기 로딩 지연, 세션에 의존하던 결제 데이터의 유실을 다룬 작업.

역할
Full-Stack Engineer
기간
2016.11 ~ 2021.03
저장 실패율
18%→에서2%
저장 관련 VOC 비중
25%→에서6%
초기 로딩
19초→에서4초
결제 데이터 유실
월 12건→에서0건
01 저장

무한 로딩으로 나타나던 저장 실패

저장 버튼을 눌러도 무한 로딩 끝에 작업물이 저장되지 않는 문제. 개별 버튼이나 API 재호출 문제로 보지 않고 캔버스 상태가 저장 데이터가 되고 저장 완료로 판단되기까지의 흐름 추적. 저장 로직을 액션 단위로 나누고 이벤트 로그로 실패 구간을 분석한 뒤 저장 구조 개선.

결과로 저장 실패율 18% → 2%, 저장 관련 VOC 비중 25% → 6%.

02 로딩과 렌더링

19초 걸리던 초기 화면

초기 진입 지연과 다수 요소를 렌더링할 때 발생하는 OOM, 브라우저 다운 문제 분석과 개선. 초기 로딩에서 시간을 쓰는 작업을 나누고 불필요한 초기 작업과 렌더링 병목을 줄여 초기 로딩 19초 → 4초.

03 결제

세션보다 오래 살아야 하는 결제 데이터

기존

  • 상품 인덱스와 결제 상태를 세션에 저장
  • 세션 유실 시 결제 데이터 누락
  • 개발팀이 로그를 찾아 유실 결제를 수동 입력

변경

  • DDD와 pipeline 구조로 DB 중심 결제 구조 재설계
  • A/B 분기로 신규 구조의 적용 비율을 점진 확대
  • 전환 중 DB 지표와 VOC 모니터링

한 번에 전환할 때의 장애 위험을 줄이기 위해 점진 전환 선택. 결제 데이터 유실 월 12건 → 0건, 결제 관련 VOC 10% 감소(상대 비율), 수동 입력 요청 소멸.

04 그 밖의 작업

상품 후기와 TypeScript

옵션별 필터링과 포토 리뷰 등 상품 후기 기능 개발, 필요한 데이터 스키마 변경과 DB Migration 수행. TypeScript를 도입해 타입을 활용한 개발과 유지보수 기반 마련.

자료 기준현재 원본 코드와 사내 문서를 보유하지 않은 과거 사례. 수치는 당시 업무 중 직접 확인하고 관리한 기록 기준이며, 최근 사례처럼 측정 환경이나 커밋 단위 근거를 제시하지 않음.
