# 포트폴리오를 사이드 프로젝트로 다시 만들기 (5) render 데모를 만들다 같은 버그를 만든 이야기

> 초안. `[다듬기]`는 본인 의견으로 채울 부분.

## 보여 주고 싶었던 것

PlotPlan에서 장비 하나를 클릭하면 CanvasNode가 2,340번 렌더링됐다. 각 노드가 선택 배열 전체를 구독해, 선택이 바뀔 때마다 새 배열 참조로 모든 노드가 다시 그려지는 구조였다. 노드가 자기 선택 여부(boolean)만 구독하도록 바꿔 1회로 줄였다. (장비 768개, CanvasNode 1,675개 합성 mock 기준)

이 차이를 읽는 대신 눌러 볼 수 있게 만들기로 했다.

## 데모 구조

- 노드 144개
- 수정 전: `useSyncExternalStore(subscribe, () => selected)` 배열 전체 구독
- 수정 후: `useSyncExternalStore(subscribe, () => selected.includes(id))` boolean 구독
- 각 노드는 렌더가 commit될 때마다 카운터를 올리고 Web Animations API로 잠깐 깜빡임

## 그리고 무한 렌더링

처음 띄운 데모는 노드 하나를 누르자 멈추지 않고 계속 깜빡였다.

원인은 카운터 표시였다. 숫자를 보여 주려고 **노드들의 부모(Grid)가 카운터를 구독**했다.

1. 노드가 렌더링됨 → effect에서 카운터 증가
2. 카운터를 구독한 부모가 다시 렌더링
3. 부모가 렌더링되니 자식 노드 전부 다시 렌더링
4. 1번으로

불필요한 렌더링을 보여 주는 데모에서, 구독 위치를 잘못 잡아 더 큰 불필요한 렌더링을 만든 것. 수정은 PlotPlan에서와 같은 원칙: **구독은 그 값이 필요한 가장 작은 범위에서.** 카운터 표시를 노드의 형제 컴포넌트(Stats)로 분리했다.

```tsx
function Grid() {
  // 카운터를 구독하지 않음
  return (
    <>
      <div>{NODE_IDS.map((id) => <Node key={id} ... />)}</div>
      <Stats counter={counter} /> {/* 구독은 여기서만 */}
    </>
  );
}
```

수정 후 측정(Playwright, 노드 두 개를 차례로 클릭):

| 구독 방식 | 마지막 클릭의 render |
| --- | ---: |
| 선택 배열 구독 | 144회 |
| 선택 여부 구독 | 2회 |

수정 후가 1이 아니라 2인 이유: 이전에 선택된 노드가 선택 해제되면서 한 번 더 렌더링되기 때문. 데모 설명에도 그대로 적었다.

## 덧붙여

- 카운터 알림은 `requestAnimationFrame`으로 묶어 한 프레임에 한 번만
- WAAPI keyframe에는 CSS 변수를 직접 쓸 수 없어 `getComputedStyle`로 현재 테마의 색을 읽어 사용
- React Compiler를 켜지 않은 이유도 이 데모 ((2)편 참고)
